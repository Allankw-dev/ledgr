# Ledgr — School Fee Management Platform (FastAPI backend)

Python/FastAPI rewrite of the Ledgr backend — same architecture and guarantees
as the original Node/Prisma version, ported to a stack that matches your
existing FastAPI experience from Hira.

**Verified working**: dependencies install cleanly, the app boots, and all
14 routes + 11 database tables register correctly (tested in this sandbox).

## Design decisions carried over

- **Multi-tenant.** Every table hangs off `school_id`. `get_school_scope`
  (in `app/core/deps.py`) is the single choke point that forces every
  request onto the caller's own school — never trusted from client input.
- **Money is `Numeric(12, 2)`, never `Float`.** Avoids the classic rounding
  bugs that come from floating-point currency math.
- **Payments are append-only.** Nothing in the `payments` table is ever
  edited or deleted — corrections happen via a linked reversal row, so the
  ledger is always auditable.
- **Invoice status is derived, not stored by hand.** `recalculate_invoice_status`
  recomputes `PAID` / `PARTIALLY_PAID` / `OVERDUE` from actual confirmed
  payments every time money moves.

## Stack

- FastAPI + Uvicorn
- PostgreSQL via Supabase, accessed through SQLAlchemy 2.0 (typed models)
- Alembic for migrations
- python-jose (JWT) + passlib (bcrypt)
- slowapi for rate limiting

## Local setup

```bash
cd backend-py
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env            # fill in DATABASE_URL and JWT_SECRET
alembic revision --autogenerate -m "init"
alembic upgrade head
uvicorn app.main:app --reload --port 4000
```

API runs on `http://localhost:4000`. Interactive docs (auto-generated by
FastAPI) at `http://localhost:4000/docs` — genuinely useful for testing
endpoints without Postman while you build the frontend.

### Supabase connection string
In your Supabase project → Settings → Database, use the **Session pooler**
URI (port 5432). SQLAlchemy manages its own connection pool, so it doesn't
need the special transaction-pooler handling Prisma requires.

## API overview (v1)

| Method | Route | Purpose |
|---|---|---|
| POST | `/api/auth/register-school` | Onboard a new school + its admin user |
| POST | `/api/auth/login` | Get a JWT |
| GET/POST | `/api/students` | List / create students |
| GET | `/api/students/{id}` | Full student record |
| GET/POST | `/api/invoices` | List / manually generate one invoice |
| POST | `/api/invoices/bulk-generate` | Generate invoices for a whole class/term |
| POST | `/api/payments` | Record a manual payment (cash/bank/cheque) |
| POST | `/api/payments/{id}/reverse` | Reverse a confirmed payment |

All routes except `/api/auth/*` and `/health` require `Authorization: Bearer <token>`.
